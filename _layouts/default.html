Bankdata Aug 2025 – Aug 2026
Lead Software Developer · Cloud Application Enablement · Enabling / Platform team

I led a three-person enabling and platform team supporting 5+ stream-aligned teams, building the shared infrastructure they used to move to the cloud and absorbing the operational complexity so they could stay focused on their product. In practice, that meant CDC pipelines off the core banking systems, Kafka-based distribution, PostgreSQL/Aurora services, and read models that decouple them from the centralised on-prem databases. Where the previous role built Bankdata's first AWS application, this one scaled the same approach across the company.

The hard part wasn't the technology. It was moving an organisation that has relied on synchronous calls for 40 years to an architecture that is eventually consistent by design. Reconciliation between cloud and on-prem is where that bites if you get it wrong, so that's where most of the design effort went. We settled on a small set of patterns teams could rely on: CQRS-style read models, idempotent consumers with the outbox pattern, versioned event contracts, and automated reconciliation against DB2 as the source of truth.

To make it self-service, we wrote a Kubernetes controller in Go that provisions databases on demand, backed by golden-path templates and shared monitoring for the data pipelines. Agentic programming became a core part of my day-to-day development.

Bankdata 2023 – 2025
External Consultant · Transactions & Categorisation · Stream-aligned team

Designed and built Bankdata's first production use of public cloud for customer data: an event-driven transaction and categorisation engine on AWS that replaced an existing COTS solution, processing 3.5 billion transactions for 1.4 million customers. Security, scale, and integration with legacy systems all had to land at the same time.

As lead developer on a team of eight, I owned the application architecture and built the solution in Quarkus and Java. CI/CD on GitHub Actions, infrastructure-as-code in Terraform, running on ECS Fargate with SQS/SNS, S3, and Aurora PostgreSQL. The slowest part of the work was the migration: pulling data from on-prem systems into AWS without breaking anything on the security, compliance, or operations side.

It's in production today, powering categorised transactions in the member banks' net and mobile banking. The patterns we settled on for secure cloud delivery have since been picked up by other Bankdata teams and became the starting point for the enablement work that followed.
